# Experiment log

Every experiment run on this machine, in order: why it ran, the exact configuration, where its outputs are and the
headline numbers. Full per-request numbers and every generated take (AI-generated audio; never publish) are under
`server/results/<experiment>/` (gitignored, local only). `server/results/INDEX.md` indexes the benchmark phases
(generated by `server/bench/collect.py`).

Machine: `vector`, 1x RTX 3090 24 GB (GPU 0, also drives the desktop: ~0.35 GB and some GPU time), driver 580.95.05
(CUDA 13.0), i9-14900K (governor powersave, EPP balance_performance), 30 GB RAM, Ubuntu 25.04. Engine: vllm 0.28.0 +
vllm-omni 0.28.0 + torch 2.13.0 cu130, `VLLM_USE_FLASHINFER_SAMPLER=0`. Model Qwen/Qwen3-TTS-12Hz-1.7B-Base
(snapshot fd4b2543), bf16 talker, fp32 Code2Wav (0.28 default). Times are Asia/Karachi.

## 2026-09-25

### E00a: first engine start (FAILED): `logs/engine_smoke_default.log`
Upstream default deploy YAML, default FlashInfer sampler. Stage-0 init JIT-compiles FlashInfer's sampling kernels and
fails: `cuda_toolkit.h:41: #error "CUDA compiler and CUDA toolkit headers are incompatible"`. pip resolved
nvidia-cuda-nvcc 13.4.92 while the CUDA runtime headers are 13.0 (CUDART_VERSION 13000), and FlashInfer's bundled
CCCL 3.3.2 refuses a compiler/header mismatch. Fix used from here on: `VLLM_USE_FLASHINFER_SAMPLER=0` (vLLM's PyTorch
top-k/top-p sampler; the talker's codec vocabulary is only 3072 entries). No JIT is needed at all then.

GPU utilisation 96-100% from c=1. No preemption was logged. The shehbaz collapse at c ≥ 48 comes from **Urdu
runaways**: the engine log shows 5 "failed generation validation; retrying once" events, all during shehbaz c48/c64
(~1.4% of 352 Urdu requests; 0 of 352 English). Without `max_new_tokens` the engine's own cap is 12 frames per text
token (~2,300 frames ≈ 186 s for a 60-word Urdu text), so each runaway occupies a batch slot for minutes before its
single built-in retry, which is what produced the 96-125 s tails. For comparison, published 3090 numbers for this
model (vLLM-Omni 0.25, PR #5253) were 4.07x at c=1 and 17.39x at c=64.

**Conclusion:** on vllm-omni 0.28 on this 3090, async_chunk **on** is better on every axis: +5-21% throughput, TTFA
0.1-0.4 s instead of the whole generation, and 3.5-4.5 GB less VRAM (async off pushed the card to 23.2 of 24 GB,
which leaves the desktop almost nothing). The older reports that async off is 15-70% faster (#4371, vLLM-Omni
0.20-0.22) predate 0.27's cached incremental decode. Keep async_chunk on; drop no_async_chunk from further screening.
