#43 [closed] CUDA device-side assert triggered on Turing GPUs (RTX 2060) during FP16 inference
URL https://github.com/QwenLM/Qwen3-TTS/issues/43
created 2026-01-24T01:44:21Z by ByAndrius

### Description

When running inference with dtype=torch.float16 on an NVIDIA RTX 2060 (Turing architecture), the model triggers a CUDA assertion failure during the token generation phase. The error persists even when using the official Gradio demo provided in the repository.

<img width="1920" height="1080" alt="Image" src="https://github.com/user-attachments/assets/f6735651-a48f-4ecb-8a9a-52c5b426bf07" />

The model seems to generate NaNs or overflows during the Multi-Token Prediction (MTP) or subtalker sampling steps when using FP16. **Native FP32 works**. Flash-Attention 2 is installed but does not resolve the numerical instability.

### Reproduction

1. Install qwen-tts on a Windows environment with an RTX 2060.
2. Run the official demo:
3. `qwen-tts-demo Qwen/Qwen3-TTS-12Hz-0.6B-custom --ip 0.0.0.0 --port 8000 --dtype fp16` (using 'uv' during test).
4. Input any text and click "Generate".

--- comment by wangxiongts (COLLABORATOR) 2026-01-26T03:31:48Z
Since we used `bfloat16` during training, and the code predictor model—being a small-parameter AR module—is extremely sensitive to precision, we strongly recommend using `float32` for inference on machines that do not support `bfloat16`, or keeping an eye on the `vllm-omni` community support (which will be closer to industrial deployment).
