--- comment by jstangroome (NONE) 2026-04-09T01:21:29Z
>What I've found that seems to work around it is just regenerating the audio.

Regenerating the audio is unsuitable in real-time streaming usage due to [a] the latency impact of discarding generated audio and retrying and [b] the difficulty of automatically detecting that the voice is incorrect.

>If the reference audio is in English, this problem can be alleviated.

This issue occurs for me in an all English setting.

However, the issue seemingly depends on some aspect of the reference audio, for example I have tried the following against Qwen3-TTS-12Hz-1.7B-Base hosted with vllm-omni mainline on an NVidia H100, and the output will not used the reference audio voice for part or all of the output at least twice in 10 attempts:

```sh
ref_text='I would like to buy an ice cream on Tuesday'
ref_audio=$(
  base64 -w0 ./ref_audio.wav
)

printf '{
    "model": "Qwen/Qwen3-TTS-12Hz-1.7B-Base",
    "input": "Okay, so you want me to be Joseph,",
    "response_format": "pcm",
    "stream": true,
    "ref_audio": "data:audio/wav;base64,%s",
    "ref_text": "%s",
    "language": "English",
    "task_type": "Base"
}' "$ref_audio" "$ref_text" >.curl.in

curl https://my-vllm-omni.example.com/v1/audio/speech \
  -H "Content-Type: application/json" \
  --data @.curl.in \
  --output .curl.out

aplay -f S16_LE -r 24000 .curl.out
```

Attempting with an alternate reference audio, I have not yet been able to reproduce the issue.
